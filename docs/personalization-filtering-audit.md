# Аудит персонализации меню и ограничений

Дата: 2026-11-27  
Ветка: `fix/remove-child-menu`  
Область: фильтрация ингредиентов, аллергии/непереносимости, вкусовые предпочтения, семейный подбор.

## Принцип продукта

Tarelka.by должен подбирать меню отдельно под каждого взрослого и собирать общее меню семьи там, где это действительно совместимо.

- **Жёсткие ограничения:** аллергены, непереносимости, исключённые продукты, тип питания, доступная техника и способы приготовления.
- **Мягкие предпочтения:** любимые продукты повышают приоритет подходящих блюд, но не отменяют ни одного жёсткого ограничения.
- **Семейное блюдо:** допустимо только если его состав подходит каждому участнику общего приёма пищи.
- **Персональный fallback:** если общего блюда нет из-за разных предпочтений или ограничений, подбираются отдельные блюда, а не пустой общий слот.
- **Семейная композиция:** общая основа и индивидуальные добавки допустимы только при явном описании состава каждой части. Состав нельзя выводить из названия блюда.

## Проверка текущей реализации

В `index.html` обнаружены следующие механизмы:

- Профили взрослых хранят отдельные `allergies`, `intolerances`, `likedIngredients` и `dislikedIngredients`.
- Нелюбимые ингредиенты исключают блюдо для конкретного человека.
- Любимые ингредиенты влияют на ранжирование совместимых блюд, а не снимают ограничения.
- Семейный подбор проверяет совместимость для каждого едока; при конфликте есть персональный подбор.
- Учитываются теги типа питания и пары «способ приготовления + оборудование».
- Составные продукты выделены в отдельный каталог идентификации, но охват пока ограничен.

## Исправления этого этапа

1. Уточнено сопоставление сладкого/болгарского перца: ранее общий алиас `перец` мог ошибочно считать чёрный или острый перец болгарским. Теперь используются более конкретные варианты названия.
2. Удалён повторяющийся ключ `Яйца` в словаре алиасов.
3. Расширены синонимы ингредиентов для пользовательских предпочтений: варианты рыбы, яйца, кунжута, перца и другие распространённые названия.
4. Расширены списки прямых ингредиентных совпадений для категорий аллергенов: молочные производные, яичные компоненты, виды рыбы/морепродуктов, соя, арахис, древесные орехи, кунжут, злаки с глютеном, сельдерей, горчица, сульфиты и люпин.
5. Непереносимости отделены от аллергий. Теперь они проверяются по отдельному словарю прямых ингредиентов. Наличие непереносимости лактозы само по себе не называется аллергией на молочный белок; глютеновые ограничения также проверяются отдельно.
6. Для непереносимостей сохраняется консервативный барьер: если ингредиентный состав или рецептура не подтверждены статусами `verified`, блюдо не допускается. Совпадение с запрещённым ингредиентом блокирует его сразу.

## Что пока нельзя считать решённым

- На текущем этапе в каталоге 118 карточек, и у всех `allergenStatus: needs_review`. Ни один рецепт не становится безопасным только из-за расширения словаря.
- Для реального допуска при аллергии необходима проверка полной рецептуры, включая составные продукты, соусы, специи, бульоны, панировку, маринады и маркировку конкретной упаковки.
- Каталог идентификации составных продуктов покрывает только часть карточек. Неизвестная марка/вариант продукта должна оставаться неизвестной; нельзя автоматически переносить состав одной марки на все продукты категории.
- Сульфиты и некоторые следовые аллергены нельзя надёжно определить только по названию ингредиента. Нужны данные этикетки конкретного продукта.
- Нынешний список предпочтений и синонимов всё ещё не является полным словарём. Новые названия и региональные варианты продуктов нужно добавлять по мере аудита каталога.
- Для некоторых аллергенов и продуктов возможны ложные совпадения. Например, «ореховое» в названии продукта и отдельные виды семян/масел требуют аккуратной классификации, а не одного общего текстового поиска.
- Текущие правила не заменяют проверку следов аллергенов и перекрёстного контакта на производстве или кухне.

## Контрольные сценарии для дальнейшего тестирования

1. Любимый продукт повышает приоритет блюда, но не позволяет включить блюдо с аллергеном.
2. Нелюбимый ингредиент исключает блюдо по синонимам и форме продукта, но не исключает несвязанные ингредиенты с похожим словом.
3. «Не люблю болгарский перец» не должно автоматически исключать блюдо только из-за чёрного перца или чили.
4. Непереносимость лактозы и аллергия на молочный белок должны оставаться разными ограничениями.
5. Целиакия/исключение глютена должны учитывать пшеницу, рожь, ячмень, солод, манку, булгур, кускус и составные продукты.
6. Разные вкусы членов семьи не должны обнулять приём пищи: нужен персональный подбор, если общего варианта нет.
7. Любая индивидуальная добавка в семейной композиции проверяется только для назначенного человека, а общая основа — для всех едоков.
8. Неизвестный состав промышленного соуса/приправы не должен объявляться безопасным по одному названию.
9. Недоступная техника или способ приготовления исключает соответствующий вариант приготовления, но не обязательно само блюдо, если есть другая явно описанная опция.
10. Если подходящего блюда нет, интерфейс должен честно показать отсутствие проверенного варианта, а не ослаблять фильтры.
