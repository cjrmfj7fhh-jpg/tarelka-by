# Тарелка.by — UX и продуктовая спецификация семейного планировщика

Статус: согласованная концепция, не описание уже реализованных функций.

## Цель продукта
Пользователь за минимальное число действий получает недельное семейное меню, индивидуальные порции, общий список покупок и оценку стоимости в выбранном белорусском магазине в рамках семейного бюджета.

## Основной сценарий
1. Выбрать один магазин: Евроопт, Санта, Green, Гиппо, ProStore или Соседи.
2. Указать количество взрослых и добавить их профили с именами.
3. Для взрослых указать известную суточную калорийную цель или запросить автоматическую оценку по необходимым параметрам. Не создавать отдельную длинную анкету о профессии/спорте.
5. Настроить расписание на неделю: кто участвует в каждом приёме пищи в каждый день.
6. Указать предпочтения, аллергии, непереносимости, бюджет и доступные способы приготовления.
7. Получить меню, порции, суммарные количества ингредиентов и список покупок.

## Семейные профили
- Каждый участник имеет имя/обращение и собственный профиль.
- Взрослые: индивидуальная калорийная цель, рассчитанная автоматически или введённая пользователем, предпочтения и ограничения.

## Ограничение первой версии
Детское меню и детские профили в текущей версии не поддерживаются. При выборе количества взрослых показывать информационное уведомление, что приложение рассчитывает меню и порции только для взрослых. Не добавлять детские поля, профили или расчёты без отдельного решения.

## Недельное расписание
- Настройка на всю неделю с возможностью редактировать отдельный день.
- Для каждого дня доступны приёмы пищи: завтрак, второй завтрак, обед, полдник, ужин и необязательный перекус.
- В каждом слоте выбираются конкретные участники.
- Поддержать повторяющиеся шаблоны (например, будни/выходные), но позволять индивидуальные исключения.
- Если участник не выбран, его порция и ингредиенты для этого слота не рассчитываются.

## Общее блюдо и индивидуальные порции
- Участники одного слота по возможности получают одно совместимое семейное блюдо.
- Порция рассчитывается отдельно для каждого взрослого.
- Количество ингредиентов рецепта масштабируется под суммарный объём порций всех участников.
- Нельзя выводить точные граммовки, калории или shopping quantities, если исходные данные о рецепте, выходе готового блюда и единицах не проверены.
- Если данные неполны, показать, что расчёт ориентировочный/невозможен, а не подставлять выдуманные значения.


## Семейные блюда: общая основа и персональные добавки
- Если полное блюдо не подходит всем, приложение может использовать только явно описанную композицию: общая основа и отдельные добавки для конкретных взрослых.
- Сначала проверяются ингредиенты общей основы для каждого участника. Затем каждая добавка отдельно проверяется по диетическому типу, аллергенам, непереносимостям и нелюбимым продуктам того человека, которому она назначена.
- Запрещено автоматически отделять мясо/рыбу от готового рецепта по названию или тегу. Для композиции нужны отдельные списки ингредиентов основы и добавок, порции, выход и проверенные данные КБЖУ каждого компонента.
- В список покупок общая основа включается один раз в количестве всех участников; индивидуальная добавка — только в количестве тех взрослых, кому она назначена.
- В меню нужно показывать состав персонально: общая основа и подпись «добавка для [имя]». КБЖУ участника — сумма его порции основы и его добавки. Если данных для суммы недостаточно, не показывать выдуманное число.
- Первый кандидат для редакторской проверки: чечевичный суп с томатами (общая вегетарианская основа) + отдельно приготовленная индейка. Это пока не готовая рекомендация: нужно утвердить отдельную рецептуру добавки, выход, граммовки и КБЖУ.
- Второй кандидат: овощное рагу с фасолью + отдельная мясная/рыбная добавка. Также требует отдельной проверенной рецептуры и расчёта.
- До проверки рецептов такие сочетания не должны попадать в меню автоматически.

## Калорийность взрослых
- Если пользователь знает норму, использовать указанную им цель.
- Если не знает, рассчитать ориентир по необходимым параметрам (как минимум возраст, пол, рост, вес и оценка общей активности). Не задавать длинные вопросы о профессии; тренировки учитывать только если это необходимо и без двойного счёта активности.
- Алгоритм стремится максимально приблизиться к индивидуальной цели, не превышая заданную цель; нижний порог гибкий, а значительный недобор сопровождается предупреждением.
- Калорийные ориентиры не являются медицинской рекомендацией.

## Предпочтения и безопасность
- Учитывать вкусы каждого участника; общее блюдо должно быть приемлемо для всех, кто ест этот слот.
- Аллергии и подтверждённые медицинские ограничения имеют приоритет над вкусом, калорийностью и бюджетом.
- При неизвестном составе/аллергенном статусе не утверждать, что блюдо безопасно для человека с аллергией.
- Учитывать возрастную пригодность, безопасную текстуру/подачу и исключать возрастно неподходящие продукты. Медицинские состояния требуют рекомендаций согласовать меню с педиатром/специалистом.

## Бюджет и магазины
- Бюджет общий для всей семьи и периода планирования.
- Список покупок рассчитывается из суммы индивидуальных порций всех выбранных участников.
- Поддерживаемые магазины: Евроопт, Санта, Green, Гиппо, ProStore, Соседи.
- Стоимость можно называть точной только при наличии актуальных проверенных цен, фасовок и доступности для выбранного магазина/региона. Иначе явно маркировать оценку или отсутствие ценовых данных.
- Не обещать соблюдение бюджета, если нет надёжных цен и данных о количестве упаковок.

## UX-принципы
- Короткий путь к результату; сначала только обязательные данные.
- Понятные подписи вместо профессионального жаргона.
- Простые настройки по умолчанию с возможностью раскрыть детали.
- Доступность для пользователей, неуверенно работающих с приложениями: ясные действия, большие области нажатия, обратимость выбора и видимые подсказки.
- Одинаково понятный сценарий в Telegram Mini App и на широком экране.
- Предупреждения показывать в момент принятия решения, а не прятать в справке.

## Границы текущей реализации
Текущая версия содержит демонстрационный каталог и неполные данные. Эта спецификация не означает, что расчёт порций, цены и интеграции магазинов уже реализованы или подтверждены.

## Первые семейные композиции — редакторские черновики

В каталог добавлены две композиции для проверки механики общей основы и персональных добавок:

1. **Томатный суп с красной чечевицей** — общая растительная основа; отдельно филе индейки для всеядных и лосось для пескетарианцев.
2. **Овощное рагу с фасолью** — общая растительная основа; отдельно индейка или лосось в зависимости от типа питания.

Правила подключения:
- общая основа масштабируется на всех участников;
- добавка назначается только участникам с соответствующим типом питания;
- в меню компоненты отображаются раздельно, с именами тех, кому назначена добавка;
- список покупок получает ингредиенты основы и только назначенных добавок; одинаковые продукты суммируются существующим агрегатором;
- для супа, приготовленного на несколько дней, ингредиенты одной варки добавляются в покупки один раз с учётом числа порций на все дни этой варки.

**Статус рецептур:** это редакторские черновики, а не проверенные опубликованные рецепты. Граммовки и КБЖУ — предварительные оценки по ингредиентам; перед выпуском требуется сверить фактический выход, пищевую ценность и состав конкретных продуктов. Аллергенный статус остаётся `needs_review`, поэтому при включённых аллергиях/непереносимостях композиции консервативно не предлагаются до проверки. Не считать эти значения точными или медицинскими рекомендациями.


## Разнообразие недельного меню
- Основные блюда обеда и ужина используют общий учёт повторов для каждого взрослого. Одно и то же блюдо не должно назначаться человеку на обед и ужин одного дня.
- Для общего блюда учитываются все участники, которые его едят; последующий личный приём пищи не должен дублировать это блюдо для того же человека.
- Подборщик сначала выбирает блюда, которых ещё не было в текущем недельном плане, и по возможности выдерживает не менее трёх дней между повторами.
- Одно и то же блюдо может появиться не более двух раз за недельный план. Если доступных совместимых альтернатив недостаточно, приложение показывает отсутствие подходящего блюда, а не бесконечно повторяет один рецепт.
- Завтраки учитываются в отдельной группе и не блокируют основные блюда.
- Супы остаются отдельным исключением: повтор на следующий обед разрешён, если пользователь выбрал приготовление одной партии на несколько дней. В список покупок ингредиенты такой партии включаются один раз.
- Разнообразие не может отменять аллергенные ограничения, непереносимости, нелюбимые продукты, тип питания и доступное оборудование.
