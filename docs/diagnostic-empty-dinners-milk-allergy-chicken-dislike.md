# Диагностика пустых ужинов при аллергии на молоко и исключении курицы

Дата: 2026-11-26  
Ветка: `fix/remove-child-menu`  
Статус: diagnostic finding / implementation not yet changed

## Воспроизведение

Тестовая комбинация, подтверждённая пользователем:
- выбран аллерген **молоко**;
- **курица** выбрана как нелюбимый продукт;
- в недельном меню у человека отсутствует ужин в 6 днях из 7.

## Подтверждённая причина

В `index.html`, функция `getDishAllergenAssessment(dish, person)`, после проверки явных ингредиентов и точечных правил адаптации выполняется условие:

```js
} else if (tagged || dish.allergenStatus !== 'verified') {
  return { status: 'blocked', reason: 'unverified_composition', adaptations: [] };
}
```

В текущем каталоге у всех 118 рецептов `allergenStatus: needs_review`. Поэтому для человека с выбранной аллергией рецепт блокируется даже тогда, когда молоко не найдено в перечисленных ингредиентах и молочный аллерген не указан в `allergens` или `allergenCandidates`.

Для молока предусмотрено лишь несколько точечных правил адаптации. Они не покрывают основную часть ужинов. Следовательно, генератор не получает достаточного пула ужинов. Это подтверждено чтением исходного кода; точное число кандидатов на конкретном профиле потребует отдельного воспроизведения в интерфейсе.

## Что проверено по курице

Нелюбимый продукт исключается персонально через `dishContainsDislikedIngredient` и словарь `ingredientPreferenceAliases`. Для выбора «Курица» используются основы `куриц`, `курин`, `цыплен`, `chicken`, что должно покрывать варианты вроде «куриная грудка». Эту часть нельзя ослаблять ради заполнения меню.

## Почему нельзя просто снять блокировку

`needs_review` означает, что состав/аллергенная разметка ещё не прошли полную редакторскую проверку. Отсутствие слова «молоко» в коротком списке ингредиентов не доказывает отсутствие молочного компонента в соусе, приправе, полуфабрикате или следов перекрёстного контакта. Автоматически объявлять такие блюда безопасными нельзя.

## Требуемое исправление

Разделить три состояния вместо бинарного «verified / заблокировано»:

1. **Явное совпадение аллергена** — блокировать, если нет точного редакторского правила адаптации; после адаптации повторно проверять полный состав и все остальные аллергии.
2. **Неполный или неизвестный состав** — не рекомендовать как подходящий человеку с аллергией; явно показывать, что подходящих проверенных блюд пока недостаточно.
3. **Полный состав редакторски проверен для конкретной версии блюда, аллерген не обнаружен** — допускать к персональному пулу только после проверки ингредиентов и идентичности составных продуктов; не путать с медицинской гарантией безопасности.

Для расширения пула ужинов нужно провести аудит именно ужинных рецептов и составных продуктов, затем добавить проверенные карточки/варианты без курицы. Нельзя массово переводить все 118 рецептов в `verified` и нельзя считать пользовательский ввод марки доказательством состава.

## Критерии приёмки следующего этапа

- Профиль с аллергией на молоко не получает блюда с молоком, сливками, сметаной, сыром, сливочным маслом, молочными полуфабрикатами и неразрешёнными составными продуктами.
- Нелюбимая курица исключается по всем вариантам написания ингредиента, включая «куриная грудка», «филе курицы», «цыплёнок» и куриный бульон/компоненты.
- Неизвестный состав не объявляется безопасным и не проходит фильтр автоматически.
- Если безопасно проверенных ужинов недостаточно, интерфейс честно показывает дефицит, а не подставляет неподходящее блюдо.
- После редакторской проверки каталог должен обеспечивать разнообразный пул ужинов на 7 дней без повторов одного и того же блюда подряд, если таких проверенных вариантов достаточно.
- Проверить персональный и общий семейный режимы, а также список покупок после адаптаций.

## Границы текущего этапа

На этом этапе выполнена диагностика и зафиксирована причина. Runtime-код, пользовательский интерфейс, статусы аллергенов и PR merge не изменялись.
